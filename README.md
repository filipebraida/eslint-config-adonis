# @filipebraida/eslint-config-adonis

ESLint for AdonisJS 7 apps with Inertia and React. It turns the architecture
of the app into lint errors: what an action, a query, a controller, a listener
and a page may do, where each file lives, how tests share the database, how
big a function may grow in each layer.

It is written for the reader that hits these errors most often: a coding
agent. Every message says where the code goes, not only what is wrong:

```
app/actions/publish_post.ts
  12:5  error  `handle` has 96 lines of code (max 80 here). Move domain rules to the
               model, the reads that decide to a query, the effects to an event; split
               independent writes into their own actions; name the remaining steps as
               private methods after the domain step  adonis/function-size
```

## Install

```bash
pnpm add -D @filipebraida/eslint-config-adonis eslint typescript
```

```js
// eslint.config.js
import { configApp } from '@adonisjs/eslint-config'
import { adonis, ui } from '@filipebraida/eslint-config-adonis'

export default configApp(...ui(), ...adonis())
```

Globs are relative to the ESLint working directory, which is the app root.
Requires Node 22+ and ESLint 10.

## What it checks

- **Layers.** One write is one action with a single `handle()`; a query only
  reads; a controller authorizes first, validates, delegates and responds,
  with CRUD methods only; data leaves through a transformer.
- **Side effects.** Never inside a transaction or a request: the action emits
  after the commit, the listener schedules, the job does the effect.
- **Data.** Models and relations over raw tables, no N+1, a public `uuid`
  generated by PostgreSQL, foreign keys that say `onDelete`.
- **Routes and HTTP.** Named routes, matchers on every param, input only
  through VineJS, redirects by route name.
- **Tests.** Entities from factories, fakes created inside the test, no
  truncate or global counts on the developer's database.
- **Screens.** Props typed from the generated `Data.*`, one default export per
  page, no internal URL literals, no role checks in the UI, the design system
  through `@shadcn/lint`.
- **Comments.** A docblock on every action, query, controller and policy; no
  comment that cites a spec criterion, a task or a ticket.
- **Size.** Lines of code per function by layer, and a nesting depth of 3.

The full list is in [Rules](#rules).

## Exceptions are written down

Some rules accept a case when the reason sits in a comment on the line above:
`db.from` on a table without a model, a `json` column a library manages, a
maintenance job that writes, `useForm` instead of the project `<Form>`. A
controller that is public on purpose declares it in the class:

```ts
export default class SignInController {
  static readonly public = true
  async create({ inertia }: HttpContext) { ... }
}
```

Anything else is fixed in the code. The comment is what the reviewer reads and
what keeps the next agent from copying the exception as the default.

## `adonis(options)`

Architecture rules, written as [ast-grep](https://ast-grep.github.io/) YAML in
`rules/<area>/<id>.yml` and run inside ESLint by `@adonisjs/eslint-ast-grep`,
reported as `adonis/<id>`. It also sets the size limits and `max-depth`.

| Option      | Default    |                                                   |
| ----------- | ---------- | ------------------------------------------------- |
| `layout`    | `'flat'`   | `'flat'` or `'modules'`; an unknown layout throws |
| `namespace` | `'adonis'` | prefix of the rule ids                            |

### Layouts

|          | `flat` (default)                                                | `modules`                                                                                 |
| -------- | --------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Backend  | `app/<layer>/`                                                  | `app/<module>/<folder>/`                                                                  |
| Routes   | `start/**/routes.ts`                                            | `start/**/routes.ts` and `app/<module>/routes.ts`                                         |
| Tests    | `tests/{unit,functional,browser}/`, helpers in `tests/helpers/` | `app/<module>/tests/{unit,functional,browser}/`, helpers in `app/<module>/tests/helpers/` |
| Frontend | `inertia/`                                                      | `app/<module>/ui/`                                                                        |

```js
// modules layout: the screens live in app/<module>/ui/
export default configApp(
  ...ui({ files: ['app/*/ui/**/*.{ts,tsx}'], registry: ['app/core/ui/components/ui/**'] }),
  ...adonis({ layout: 'modules' }),
)
```

Rules about the shape of code are layout-agnostic: their globs cover both
layouts. Rules about where files live belong to one layout and sit in
`rules/<area>/flat/` or `rules/<area>/modules/`. Module names are never
listed: any folder directly under `app/` is a module.

## `ui(options)`

For the screens:

- the AdonisJS React preset, with `react-hooks` 7 (React Compiler rules);
- `@eslint-react` in `strict-typescript`;
- recommended `jsx-a11y`;
- `@shadcn/lint`: raw colors, arbitrary values, inline styles, classes Tailwind
  does not know, dynamic classes, and registry components restyled by a
  screen. Registry components are skipped: they define the styles.

| Option      | Default                        |                                                                        |
| ----------- | ------------------------------ | ---------------------------------------------------------------------- |
| `files`     | `['inertia/**/*.{ts,tsx}']`    | the screens to check                                                   |
| `registry`  | `['inertia/components/ui/**']` | the design system components                                           |
| `ui`        | `'~/components/ui'`            | import alias of the registry                                           |
| `note`      | none                           | text appended to every design system error, e.g. where the tokens live |
| `contracts` | `CONTRACTS`                    | what each registry component lets a screen decide (`no-restyle`)       |

`CONTRACTS` is exported: it lets a screen set the layout, spacing and
typography of cards and table cells, and the shape of a skeleton. Extend it
for your own components.

## Side effects

An external effect (mail, notification, file, HTTP) cannot be rolled back, so
it never runs inside a transaction and never inside the request.

| Where                             | May                                                                                                               | May not                                                  |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| Action                            | write, in a transaction; emit the event after commit (`events.X.dispatch(id)`)                                    | any external effect, not even scheduling one             |
| Listener                          | schedule: `XJob.dispatch({ id })`, or `mail.sendLater(...)` for a single e-mail when the project has no job queue | send (`mail.send`), call out, read or write the database |
| Job (`@nemoventures/adonis-jobs`) | decide whom to reach, execute the effect idempotently                                                             | write to the database except through an action           |

Not enforceable by lint: an event emitted after commit is lost if the process
dies in between. When an event must never be lost, use a transactional outbox
(write the event in the same transaction, publish it from a dispatcher).

## Test isolation

The `tests` rules encode how tests share the developer database and the
machine with the developer:

- **The database is the developer's.** Tests never migrate, seed or truncate
  it, and never know what is already there. Every spec that writes wraps each
  test in `testUtils.db().wrapInGlobalTransaction()`, so what it created is
  rolled back. Browser specs cannot share that transaction and are exempt.
- **Assert on deltas, scoped by what the test created.** No count over a whole
  table: `db.assertHas('reviews', { post_id: post.id }, 1)`,
  not `db.assertCount('reviews', 1)`. Compare parsed ids, never an id as a
  substring of JSON.
- **Fakes are created with `using`, inside the test.** `using fake = mail.fake()`
  restores the fake when the test ends, even when an assertion throws first.
  `mail`, `emitter`, `drive` and `facteur` return a disposable fake; none of
  them needs `.restore()`. `@nemoventures/adonis-jobs` has no fake: stub
  `XJob.dispatch` with sinon and `sinon.restore()` in `group.each.teardown`.
- **Entities come from factories**, with states for the variations, in the
  spec and in the helpers alike.
- **No real files, network or mail.** Uploads go through `drive.fake()` with a
  buffer generated in the test; `fetch` is stubbed; mail is faked. A leaked
  side effect outlives the test: files in `tmp/uploads`, e-mails in Mailpit.
- **No skipped tests.** A skipped test is green without covering anything.

What the lint cannot see: a request, action or listener that sends mail or
writes files deep inside the code under test. `spec-mail-needs-fake` only
catches `mail.send` written in the spec itself.

## Size and depth

`function-size` counts the lines of code of each named function (blank and
comment lines do not count) against the limit of its layer, and the message
says where the extra code belongs. The limits (`SIZE_LIMITS` in
`presets/adonis.js`) sit above what the model projects write, so a function
past them is usually doing another layer's work:

| Layer                          | Max           | Where the excess goes                                                                                                                                      |
| ------------------------------ | ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| actions                        | 80            | domain rules to the model, reads to a query, effects to an event, independent writes to their own actions, steps to private methods named after the domain |
| controllers                    | 100           | authorize, validate, delegate, transform, respond; the rest to the action, the query or the transformer                                                    |
| queries                        | 130           | repeated filters to model scopes, screen blocks to their own queries                                                                                       |
| services                       | 120           | one function per step                                                                                                                                      |
| jobs                           | 60            | the decision to a query, the write to an action                                                                                                            |
| listeners                      | 20            | only the dispatch                                                                                                                                          |
| models, policies, transformers | 40            | one method per rule, verb or screen                                                                                                                        |
| pages, components, layouts     | 200 (warning) | one component per block in `components/<resource>/`                                                                                                        |

When none of that applies, disable the rule on that function with the reason
in the comment. `max-depth` is 3 in `app/`, `inertia/` and `start/`: past it,
invert the condition and return early.

## Adding a rule

1. Write `rules/<area>/<id>.yml`. The file name is the rule id. A rule that
   only makes sense in one layout goes in `rules/<area>/flat/` or
   `rules/<area>/modules/`; the same id may exist in both.

   ```yaml
   id: query-no-writes
   language: typescript # tsx for files that may contain JSX
   files: ['app/queries/**/*.ts']
   severity: error
   metadata:
     description: 'Queries never call `save`, `create`, `delete`...'
   message: '`.$METHOD()` in a query.'
   note: 'A query only reads; writes go to an action in app/actions/.'
   rule:
     kind: call_expression
     has:
       field: function
       kind: member_expression
       has: { field: property, pattern: $METHOD, regex: '^(save|create|delete)$' }
   ```

   - `message` interpolates captures such as `$METHOD`; `note` says how to fix it.
   - `metadata.description` is the line of the catalog in this README.
   - `files` and `ignores` use ESLint glob semantics. A rule about where a file
     lives matches the whole file with `rule: { kind: program }`.
   - `regex` is Rust regex: no look-ahead or look-behind; use `not` and `any`.
   - A YAML mapping cannot repeat a key: combine two `any` or `has` with `all`.
   - `fix` is not supported.

2. Write `rules/<area>/<id>.test.yml` with the cases, `file` relative to the app root:

   ```yaml
   valid:
     - { file: app/queries/reviews.ts, code: 'Review.query().first()' }
   invalid:
     - { file: app/queries/reviews.ts, code: 'review.save()' }
     - { file: app/queries/reviews.ts, code: 'a.save(); b.delete()', errors: 2 }
   ```

3. Run `pnpm test`. Each case runs through ESLint with the full
   `adonis({ layout })` preset: the layout the file declares (`layout: modules`
   at the top of the `.test.yml`), else the layout of its folder; a
   layout-agnostic rule runs with both. The suite also fails when a rule has no test file, its YAML has a
   duplicated key, or its id does not match the file name.

4. Run `pnpm catalog` to rewrite the catalog in this README. The suite fails
   while it is stale, or while a rule has no `metadata.description`.

A rule that ast-grep cannot express is an ESLint rule in JS next to the YAML
ones (`rules/routes/route-param-matcher.js`, `rules/size/function-size.js`),
registered in `JS_RULES` in `presets/adonis.js`, with its cases in a
`.test.yml` like any other.

## Releasing

Bump `version` in `package.json`, commit, then tag and push:

```bash
git tag v0.2.0 && git push origin main v0.2.0
```

The `release` workflow runs the checks, verifies that the tag matches the
version, publishes to npm with provenance through trusted publishing (no npm
token is stored in the repository) and creates the GitHub release. A version
with `-alpha`, `-beta` or `-rc` goes to that dist-tag and is marked as a
prerelease.
